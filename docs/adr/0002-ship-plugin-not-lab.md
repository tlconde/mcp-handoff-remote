# Ship the plugin, not the lab

**Status:** accepted · `95a7ae3` (2026-08-10), extended 2026-08-10 with proof ownership

## Decision

This repo is the publishable artifact: runtime, MCP surface, hooks, plugin manifests, and install
docs. Smokes, protocol tests, drift evals, design specs, and evaluation receipts stay on the
maintainer's disk (gitignored / notebook) and do not ship.

## Proof ownership and mirror direction

The first version of this decision named what leaves and not who keeps it, and that gap produced a
live contradiction: `AGENTS.md` went on listing `*-smoke.js` and `protocol-test.js` as shared code
that **this repo leads**, while the same files were no longer tracked here at all. An agent could
comply with this ADR and still be instructed to mirror the lab back in.

| lane | owner (leads) | mirror direction |
|---|---|---|
| Runtime (`handoff-*.js`, `mcp-handoff.js`, `server.js`, `bin/`, `hooks/`, `plugin.json`, `mcp.json`) | **this repo** | here → notebook |
| Proofs (`*-smoke.js`, `protocol-test.js`, `drift-eval.js`, `forwarder-runbook.js`) | **`<PROOF_OWNER>`** | proof owner outward |
| Design specs (`*-SPEC.md`, `THREAT-MODEL.md`) | **`<PROOF_OWNER>`** | proof owner only |
| Receipts, trials, pitch material | notebook | never travels here |

`<PROOF_OWNER>` is an open question for the operator — the existing notebook, or a future private
`handoff-lab` repo. It is left as a visible fill-in rather than guessed, because the two answers
imply different mirror tooling. What is already decided, and is the half that was getting acted on
wrongly: **this repo does not own or lead the proofs.**

## Rejected alternatives

1. **Keep the workbench tracked here.** Mixed personal session evidence into a repo intended for
   public release and forced every clone to carry the lab.
2. **Re-track the lab to silence the doctrine contradiction.** Considered and refused — it fixes a
   sentence by reversing the decision. The contradiction is repaired by writing ownership down,
   not by restoring what was deliberately removed.
3. **Two trees with the public one generated by an export script.** Genuinely attractive: the
   public repo would be born with clean history and the scrub gate would never need passing. Not
   taken now — it is a larger build than the packaging slice, and it does not remove the need for
   this ADR, since the export boundary needs the same ownership table to know what to export.

## Enforcement

`.gitignore` stops future adds; `git rm --cached` in `95a7ae3` and `fd06228` removed what was
already tracked. Neither touches history — see the publication gate below. The ownership table is
enforced by `AGENTS.md`, which agents read before acting, and by nothing else: there is no check
that fails when a smoke file reappears here. **That is a known soft spot.**

## Coupling to the publication gate

Untracking is not scrubbing, and this decision does not clear the gate. Measured 2026-08-10 on this
tree: `mcp-roundtrip-evals/` in **5** commits, `docs-seed/` in **5** commits, and **25** matches for
the `sess_`-class id pattern across `git log --all -p`. HEAD is clean; history is not. See
`AGENTS.md` → publication gate, and the runbook in `docs/runbooks/history-scrub.md`.

## What would reopen this

- The operator chooses the export-script model (rejected alternative 3), which supersedes the
  boundary rather than the ownership table.
- The proof lane finds an owner that is *this* repo — which would mean the publication decision
  itself changed.
- A shipped doc is found claiming something only a lab-side test asserts. That is the signal the
  boundary has gone soft in prose while holding in git.
